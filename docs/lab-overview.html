Project scope: what I built

I built a small Flask application, added functional and header tests, containerised it, and integrated Bandit and ZAP into GitHub Actions. I then tested whether the required CI check actually prevented merging when a security rule failed.

The scope is continuous integration and security validation. Production deployment, cloud infrastructure, dependency/image vulnerability scanning and authenticated testing are not implemented.

03 / Experiments & evidence

Three lessons, backed by observable results.

SAST / B105

A green scan is not a fix.

Bandit detected a dummy hardcoded password. Renaming the variable made the scan pass while leaving the string in place.

Resolution: removed the unused dummy value and its comment.

What this demonstrated

Rules have detection limits. Review the underlying change, not just the check colour. Only synthetic data was used.

SAST experiment notes →
DAST / 10021

Find → fix → verify.

Added the missing response header through Flask's after_request hook.

X-Content-Type-Options: nosniff

Evidence: header test passed, curl confirmed it, and finding 10021 disappeared on rescan.

Verification scope

This confirms the header finding was absent within the scanned scope, not that the application is free of vulnerabilities.

DAST verification notes →
MERGE GATE / 10038

Test the failure path.

Temporarily classified the existing missing-CSP finding as FAIL. ZAP exited with code 1; CI failed and GitHub blocked merging.

Recovery: reports still uploaded. Reverting the policy restored a passing check.

What was—and was not—fixed

This tested gate enforcement. CSP remains unresolved; a regression of rule 10021 was not directly tested.
